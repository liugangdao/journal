# 手动交易日志：设计说明

日期：2026-11-06
状态：待用户确认

## 1. 为什么做

用户手动下单（电脑上开交易所网页为主，有时用手机 App），典型流程：判断趋势来了 → 等高二入场 → 止损放在主要低点 → 按止损距离定仓位、单笔亏损不超过账户 1% → 按规则出场。

用户想用完整的交易记录回答：**我赚的是什么钱、亏的是什么钱、哪些策略有可重复的优势。** 这个工具要做到两件事：

1. 下单那一刻能快速、按事前的口径记下一笔（理由先写，避免事后编故事）。
2. 打开就能看到自己有哪些策略，以及每个策略（按版本）有没有统计上站得住的优势。

## 2. 目标 / 非目标 / 反目标

**目标**
- 记录开仓、平仓，自动算 1R、仓位和 R 倍数。
- 策略可新增、编辑，规则修改形成版本；新版本样本从零开始，旧版本单独统计、只读保留。
- 策略面板按当前版本给出期望、置信区间和结论，并展示附加检验（见第 6 节）。
- 电脑和手机都能用，两边看到同一份数据。
- 用户自行部署（自己的服务器），本仓库只交付代码和部署说明。

**非目标**
- 不对接交易所 API，不自动导入成交。
- 不单独记录手续费、滑点（出场价按实际成交价填，成本已含在内）。
- 不记录市场状态。
- 不做多用户。

**反目标（做了等于失败）**
- 样本很少时给出醒目的"有优势"结论，诱导用户过早下结论。结论必须受样本量门槛和置信区间约束。
- 记录一笔要填很多字段、步骤繁琐，导致用户下单时不愿意记。
- 改规则后把新旧版本的交易混在一起统计。

## 3. 形式与技术选型

用户已确定：后端用 Go，编译成单个可执行文件，部署到能运行程序的服务器（如 us-vps）。其余为 Claude 的决定，用户可推翻。

- 放在本仓库新目录 `journal/`，与 `research/`、`freqtrade/` 平级，是独立的 Go module（`journal/go.mod`），不影响仓库里的 Python 代码。
- 后端：Go（1.22+，使用标准库 `net/http` 的方法 + 路径路由，不引入 Web 框架）。
- 数据库：SQLite，驱动用纯 Go 的 `modernc.org/sqlite`（不需要 cgo，可在任意平台交叉编译 `GOOS=linux GOARCH=amd64`）。启用 WAL 模式。
- 前端：无构建步骤的静态页面（`journal/web/` 下 HTML + CSS + 原生 JS），通过 `go:embed` 打包进可执行文件，同一进程提供页面和接口。不加载任何外部 CDN 或字体，使用系统字体栈。（2026-11-13 更新：数字与英文改用随程序内嵌的 Inter 可变字体，仅拉丁子集约 48 KB，许可证 SIL OFL 1.1 见 `web/fonts/Inter-OFL.txt`；仍不访问外网，中文继续用系统黑体。）
- 依赖尽量少：除 SQLite 驱动外只用标准库。
- 代码结构建议：`cmd/journal/main.go`（启动、配置）、`internal/store`（建表与读写）、`internal/stats`（纯函数统计，不依赖数据库和 HTTP）、`internal/api`（HTTP 处理与鉴权）、`web/`（前端）。
- 鉴权：单用户口令。启动时从环境变量 `JOURNAL_TOKEN` 读取口令，未设置则拒绝启动。前端登录页输入一次后存入 `localStorage`，之后每个请求带 `Authorization: Bearer <token>`；比较口令用常量时间比较。HTTPS 由部署时的反向代理负责。
- 配置（环境变量）：`JOURNAL_TOKEN`（必填）、`JOURNAL_DB`（数据库文件路径，默认 `./journal.db`）、`JOURNAL_ADDR`（监听地址，默认 `127.0.0.1:8800`）。
- 数据库文件加入 `.gitignore`。
- 构建：`cd journal && go build -o journal ./cmd/journal`；运行：`JOURNAL_TOKEN=... ./journal`。

## 4. 数据模型

**settings**（单行）
- `risk_pct`：默认单笔风险比例，默认 1.0（%）。
- `min_sample`：开始评估的最少笔数，默认 30。

**strategies**
- `id`、`name`（唯一）、`created_at`、`archived`（布尔，归档后不在面板默认显示，但数据保留）。

**strategy_versions**
- `id`、`strategy_id`、`version_no`（从 1 递增）、`created_at`。
- `rules`：规则说明文本（入场条件、止损放在哪、怎么出场）。
- 停用条件（属于版本的一部分，均可留空表示不启用）：
  - `kill_recent_n` + `kill_recent_below`：最近 N 笔的平均 R 低于该值时触发（例：30 笔、0）。
  - `kill_max_dd_r`：该版本累计 R 曲线的最大回撤超过该值（单位 R）时触发（例：10）。
- 版本一旦创建即只读。编辑策略名称不产生新版本；修改规则或停用条件产生新版本，新版本成为当前版本。

**trades**
- `id`、`version_id`（开仓时自动取策略当前版本，之后不变）。
- 开仓字段：`symbol`、`side`（long/short）、`entry_price`、`stop_price`、`equity`（账户权益，默认带上一笔的值）、`risk_pct`（默认取设置）、`qty`（默认按 `equity × risk_pct ÷ |entry − stop|` 计算，用户可改成实际下单数量）、`entry_reason`（必填，一句话）、`opened_at`。
- 平仓字段：`exit_price`、`exit_reason`（stop/target/manual 即 止损/止盈/主动离场）、`followed_rules`（布尔）、`review_note`（选填）、`high_price` / `low_price`（选填，持仓期间最高价、最低价）、`funding_fee`（选填，付出为正、收到为负，计价货币）、`closed_at`。
- `status`：open / closed。
- 已平仓的单可以修改或删除（删除需页面内二次确认）。

## 5. 计算口径

- 方向系数 `d`：做多 +1，做空 −1。
- 计划风险金额 `risk_amount = qty × |entry − stop|`。
- 盈亏 `pnl = d × (exit − entry) × qty − funding_fee`（`funding_fee` 为空按 0）。
- **R 倍数 `R = pnl ÷ risk_amount`。**
- 盈利笔：R > 0；亏损笔：R ≤ 0。
- 选填了最高价、最低价时：
  - 最大浮盈 MFE（单位 R）：做多 `(high − entry) ÷ |entry − stop|`，做空 `(entry − low) ÷ |entry − stop|`。
  - 最大浮亏 MAE（单位 R）：做多 `(entry − low) ÷ |entry − stop|`，做空 `(high − entry) ÷ |entry − stop|`。
  - 利润回吐：`MFE − R`。
- 开仓时校验：止损必须在入场价的亏损一侧（做多止损 < 入场，做空止损 > 入场），否则拒绝保存。

## 6. 统计（按策略版本，只算已平仓）

基础：
- 笔数、胜率、平均盈利 R、平均亏损 R、每笔期望 E（平均 R）、R 的标准差、累计 R 序列（按平仓时间）、最大回撤（R）、最长连亏笔数。

置信区间：
- 对该版本的 R 序列做 bootstrap 重抽样 2000 次，取平均值的 2.5% 和 97.5% 分位作为 95% 区间。使用固定随机种子，保证同一数据结果稳定。

结论标签（优先级从上到下）：
1. 触发停用条件 → **触发停用**（红）
2. 笔数 < `min_sample` → **样本不足**（灰）
3. 区间下限 > 0 → **有优势**（绿）
4. E > 0 → **有苗头**（黄）
5. 其余 → **暂无优势**（红）

附加检验（每个版本都算，结果在策略详情里展示，必要时在面板行内给出警示图标）：
- **多空分开**：做多、做空各自的笔数和 E。若一边 E > 0、另一边 E ≤ 0 且两边都有至少 10 笔，提示"收益可能来自单边行情"。
- **去掉最好的 5 笔**：剩余交易的 E。若原 E > 0 而去掉后 ≤ 0，提示"收益集中在少数几笔"。笔数 ≤ 5 时不计算。
- **按规则 / 违规分开**：各自笔数、E、累计 R。
- **入场 / 出场质量**：填了最高最低价的交易的平均 MFE、平均 MAE、平均利润回吐，并注明有多少笔填了。
- **停用条件状态**：每条条件的当前值和阈值，是否触发。

全局汇总（面板顶部）：
- 所有已平仓交易的总 R。
- 按规则执行率（`followed_rules` 为真的占比）。
- 违规单累计 R。
- 已试过的策略数和版本总数，并附一句提示：试过的越多，越容易碰巧出现好看的结果。

## 7. 页面

视觉：交易终端式的信息密度。两套主题可切换：**护眼**（默认，暖灰纸色底、低对比度）和**柔和深色**（深灰底、浅灰字），由用户在顶栏切换，记在本机 `localStorage`。所有颜色都用 CSS 变量定义，包括曲线和置信区间条。前端模板见 [2026-11-06-trade-journal-template.html](2026-11-06-trade-journal-template.html)（静态示例数据），实现时以它为视觉和信息层级的基准。数字用等宽数字，盈亏用绿/红语义色，与强调色分开。

页面与交互：
1. **登录**：输入口令。
2. **策略面板（首页）**
   - 顶部：全局汇总，右上角"＋ 记一笔"按钮。
   - 持仓中列表：每笔一行，带"平仓"按钮。
   - 策略列表：每个策略一行，显示当前版本号、笔数、E、置信区间条（0 处有刻度线）、结论标签，附加检验有警示时显示小图标。
   - "＋ 新建策略"入口；已归档策略可展开查看。
3. **记一笔（开仓）**：弹出面板或独立视图。选择策略后显示其当前版本规则摘要；填入场价、止损价后实时显示 1R 金额、建议数量、名义价值；理由必填。
4. **平仓**：填出场价、出场原因、是否按规则执行；选填复盘、最高价、最低价、资金费。保存前实时显示这笔的 R。
5. **策略详情**：
   - 当前版本：规则全文、停用条件、全部统计和附加检验、累计 R 曲线（SVG，零线、终点高亮）。
   - 版本历史：每个版本的创建日期、规则内容、统计摘要，可切换查看；旧版本只读。
   - 该版本的交易列表，可点开修改或删除。
   - "编辑规则"会提示"保存后将创建 vN+1，新版本从零开始统计"。
6. **设置**：默认风险比例、最少样本数；导出 / 导入 JSON 备份（导入为整库替换，需二次确认）。

响应式：手机宽度（约 400px）下单列布局，表格行转为卡片，"记一笔"表单单列、输入框适合触屏。

## 8. 接口（建议形态，实现者可微调）

所有 `/api/*` 需要 Bearer 口令。

- `GET /api/overview`：全局汇总 + 各策略当前版本统计摘要 + 持仓中列表。
- `GET/POST /api/strategies`，`PATCH /api/strategies/{id}`（改名、归档）。
- `POST /api/strategies/{id}/versions`（新规则 / 停用条件 → 新版本）。
- `GET /api/versions/{id}/stats`：该版本完整统计和交易列表。
- `POST /api/trades`（开仓），`POST /api/trades/{id}/close`，`PATCH /api/trades/{id}`，`DELETE /api/trades/{id}`。
- `GET/PUT /api/settings`。
- `GET /api/export`，`POST /api/import`。

## 9. 测试

测试用 Go 标准库 `testing`，放在各包旁边（`go test ./...`）。

- `internal/stats`：R 计算（多空、资金费）、MFE/MAE、bootstrap 区间在固定种子下稳定、结论标签各分支、附加检验各提示的触发与不触发、停用条件（含笔数不足 N 时不判定）。用表驱动测试。
- `internal/api`：用 `net/http/httptest` 和临时 SQLite 文件跑一遍完整流程：无口令被拒 → 建策略 → 开仓（止损放错一侧被拒）→ 平仓 → 改规则产生 v2 → v2 统计从零开始、v1 统计不变 → 导出再导入数据一致 → 非法导入整体拒绝。
- 按仓库约定，运行测试和构建需用户授权。

## 10. 部署说明（交付文档，不由本任务执行）

`journal/README.md` 写明：

- 本地构建和交叉编译命令（`GOOS=linux GOARCH=amd64 go build ...`）。
- 拷贝到服务器、设置 `JOURNAL_TOKEN` / `JOURNAL_DB` / `JOURNAL_ADDR`、启动。
- systemd 服务示例文件 `journal/deploy/journal.service`：独立用户运行，口令放在 `EnvironmentFile` 里，不写进服务文件。
- 反向代理（Caddy 或 Nginx）启用 HTTPS 的最小示例。
- 数据备份：用导出功能，或停服后复制 SQLite 文件（WAL 模式下要连同 `-wal` 文件一起复制，或先 checkpoint）。

## 12. Claude 做的决定（供用户核对）

- 技术栈细节：标准库 `net/http` 路由、纯 Go SQLite 驱动 `modernc.org/sqlite`、`go:embed` 内嵌无构建原生前端，放在 `journal/`（用户只定了 Go + 单文件部署）。
- 单口令鉴权，HTTPS 交给反向代理。
- 不用外部 CDN 和网络字体（字体文件可随程序内嵌，见上文 2026-11-13 更新）。
- 样本门槛 30 笔；bootstrap 2000 次、固定种子。
- 盈利笔定义为 R > 0。
- 多空提示门槛：两边各至少 10 笔。
- 资金费符号：付出为正。
- 建议数量可被用户改成实际下单数量，R 按实际数量计算。
- 停用条件属于版本的一部分，修改它也产生新版本。
- "最近 N 笔"按平仓时间排序；该版本已平仓笔数不足 N 时，这条条件不判定。
- 时间以 UTC ISO 字符串存储，前端按浏览器本地时区显示。
- 持仓中的单也可以修改或删除。
- 全局汇总包含已归档策略的交易。
- 导入时校验 JSON 结构，不合法则整体拒绝，不做部分导入。
