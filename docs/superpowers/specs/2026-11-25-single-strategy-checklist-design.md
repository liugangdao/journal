# 单一策略与执行检查清单

日期：2026-11-25
状态：待用户确认

## 意图

现有设计用来比较多个策略谁有优势。用户精力有限，决定只保留并优化一个策略（1 小时 Vegas 顺势，突破前高或回调高二/低二入场），重点保证每一笔都完全按规则执行。

工具因此改为同时回答两个问题：

1. **策略本身有没有优势？** 只看按规则执行的单子。
2. **我执行得怎么样？** 按规则执行率、违反了哪几条、每种违规花了多少 R，以及全部单子的实际结果比按规则单差多少。

## 目标 / 非目标 / 反目标

**目标**

- 系统里只有一个策略，规则和清单写在代码里；规则更新时改代码，启动时自动生成新版本。
- 开仓时按规则逐项勾选，代替自由文本理由；未满足的规则项自动记为违规开仓。
- 平仓时记录具体的执行偏差，代替单个“是否按规则”勾选框。
- 首页同时展示策略优势和执行情况。

**非目标**

- 不能在页面上新建、改名、归档策略，也不能编辑规则或清单。
- 不自动识别图形，也不接行情数据，所有项都由用户勾选。

**反目标**

- 违规时禁止保存。这会让冲动下的单子不被记录，而这类单子最需要记录。
- 开仓步骤明显变慢。清单要能在一屏内勾完。
- 把违规单混进“策略有没有优势”的结论，或者只展示按规则单、隐藏实际执行结果。

## 策略定义（代码里）

- 策略名称、各版本的规则全文、清单条目、停用条件都定义在 Go 代码里（`internal/rules`），版本号随代码递增。
- 版本 1 的规则全文就是用户 2026-11-25 发来的策略原文，清单见下文。停用条件暂不设置。
- 启动时如果代码里的最新版本号大于数据库里的，就写入新版本，新版本成为当前版本，新旧样本分开统计，与现在的版本机制相同。已写入的版本不变。
- 以后改规则或清单：在代码里追加一个新版本（不修改旧版本），重新部署即可。

## 旧数据不兼容

这版改动大，用户决定旧数据全部不要，不做迁移。

- 数据库直接按新结构建表，schema 版本记为 4。打开版本低于 4 的旧数据库时拒绝启动，提示“旧版数据库不再兼容，请删除或换一个 JOURNAL_DB 路径”。程序不自动删除旧文件。
- 账户权益、设置随旧库一起不要，新库里重新设置。
- 删除旧的建策略、改名、归档、新建版本的接口和页面，以及 1 → 2 → 3 的迁移代码。
- 导入只接受版本 4 的备份。备份里的策略版本必须与代码中同号版本一致，缺少的新版本在导入后自动补上。
- 以后的版本改动会小很多，从版本 4 起再做迁移兼容。

## 开仓清单（版本 1）

分三类：**规则项**未满足则这笔记为“违规开仓”；**注意项**只记录、只提示，不算违规；**必填项**不填不能保存。

| 环节 | 内容 | 类型 |
| --- | --- | --- |
| 背景 | 1H Vegas 方向：多 / 空。与开仓方向不一致即违规 | 规则项（选择） |
| 背景 | K 线没有反复穿越 Vegas，已有一方掌控局面 | 规则项 |
| 背景 | 刚有一波大的突破或跌破，还没回调（高潮行情反弹会很远） | 注意项 |
| 画线 | 已画 Vegas、趋势线、通道线、主要高点或主要低点 | 规则项 |
| 趋势阶段 | 前期 / 中期 / 后期 / 不确定 | 必填项 |
| Setup | 突破前高 / 回调高二·低二 | 必填项 |
| 突破 | 趋势明确，前一波或这一波回调较小 | 规则项（仅突破） |
| 突破 | 没超过约 20 根 K 线，或已考虑回调和阻力位的反应 | 规则项（仅突破） |
| 回调 | 回调到明确的阻力位（主要高点或主要低点） | 规则项（仅回调） |
| 回调 | 是高二或低二 | 规则项（仅回调） |
| 回调 | 信号 K 线较好 | 规则项（仅回调） |
| 入场 | 用 stop order 入场 | 规则项 |
| 止损 | 设在主要高点之上或主要低点之下一点；趋势很强、入场很远时设在 1/2 处 | 规则项 |
| 止损 | 做空填主要高点价格，做多填主要低点价格（标签随方向切换） | 必填项（供后续分析，不做校验） |
| 出场 | 移动止损 / measured move / 分仓 | 必填项 |
| 出场 | 目标价（选 measured move 时填） | 选填 |
| 心态 | 这笔亏损我能接受 | 规则项 |

- 只显示所选 Setup 对应的规则项，另一类不保存。
- 规则项默认不勾，Vegas 方向默认跟随开仓方向。
- 页面实时显示未满足的规则项；有违规时保存按钮文字变为“记为违规开仓”，仍可保存。
- 原来的“开仓理由”改为选填备注。

## 平仓偏差

平仓时勾选实际发生的偏差，勾上任一项即为违规：

- 持仓中手动改了止损（计划内的移动止损不算）
- 提前离场（没到止损、目标，也不是计划内的移动止损出场）
- 加仓或其他计划外操作

**按规则执行** = 开仓无违规且平仓无偏差，由后端计算，不再让用户手动勾选。

## 数据

新建表，不保留旧列。`trades` 在原有开仓、平仓字段基础上增加：

| 字段 | 说明 |
| --- | --- |
| `checklist` | JSON，开仓清单各项的值，键名按版本固定，后端校验 |
| `setup` | `breakout` / `pullback` |
| `key_level` | 主要高点（做空）或主要低点（做多）价格 |
| `exit_plan` | `trail` / `measured_move` / `scale_out` |
| `target` | 目标价，选填 |
| `deviations` | JSON 数组，平仓偏差的键名 |

- `phase`（趋势阶段）改为必填，`strategies` 去掉 `archived`。
- `followed_rules` 继续保存，平仓时由后端算出并写入。
- 开仓违规项不落库，按 `checklist` 和该交易所属版本的清单定义计算。
- 清单字段开仓后不能修改，与趋势阶段相同，补丁接口不接受这些字段。

## 首页与统计

首页从上到下：

1. 账户权益、交易时段（不变）。
2. **策略优势**（当前版本，只算按规则单）：笔数、E、置信区间、结论标签、累计 R 曲线。
3. **执行情况**（当前版本）：
   - 按规则执行率、最近 10 笔中违规的笔数。
   - 全部单与按规则单对照：各自的笔数、E、累计 R，差值就是执行损耗。
   - 违规单累计 R。
4. 持仓中列表、“记一笔”。

版本详情：

- **按 Setup**：突破、回调各自的笔数和 E（按规则单）。
- **按违规项**：每个开仓规则项和每种平仓偏差的触发次数和累计 R，按代价排序。
- **注意项对照**：勾了“刚有大突破或跌破”的单与没勾的单各自的笔数和 E。
- 现有的按趋势阶段、多空、去掉最好 5 笔、MFE/MAE 保留，统计范围为按规则单。
- 版本历史可切换查看旧版本，只读。

样本不足最少样本数的分组变淡，只给描述性数字，沿用现有规则。
